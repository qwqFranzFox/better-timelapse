# 手感规划（下一阶段）

这份文件只说一件事：**在相机上把 app 用起来是什么感觉**，以及下一阶段按什么顺序改它。
它不重复 [PLAN.md](PLAN.md) 的架构与里程碑，只写在真机上按下去、看见什么、以及哪里会让人骂人。

---

## 0. 为什么手感在这个项目里算功能

1. **相机上没有触摸屏。** 可用的键只有：方向键四个、中心、TRASH、MENU、滚轮与顶部拨盘。变焦杆这个键机身**不送给 app**（[PLATFORM-FACTS](PLATFORM-FACTS.md) §6），AEL / C1 / DISP / PLAY 目前被吞掉且无绑定。
2. **一次拍摄 30 分钟到几小时，用户会走开。** 回来时他只看一眼屏幕，那一屏必须能让他判断「成了没有、丢了几张、还能不能接着走」。
3. **误触的代价是整晚。** 老 app 的 U-01 就是这条：MENU 或 TRASH 一按，app 退出、运行丢失、什么都不问（[PAIN-POINTS](PAIN-POINTS.md) U-01/U-04）。
4. 因此本项目的两条手感判据（比「好看」重要得多）：
   - **任何一次误触都不能丢掉已经拍成的东西。**
   - **任何一屏都不能说出相机没做到的事**（U-06/U-07 的教训：数了没拍的帧、报了没生效的设置）。

## 1. 现状：键位与它们的实际行为

| 键 | 现在做什么 | 评价 |
|---|---|---|
| 滚轮 / 拨盘 | 当前行 ± 最小档 | 好；与 recipe-lab 的语义一致（[DECISIONS](DECISIONS.md) A6） |
| ← / → | 当前行 ± 大档 | 好 |
| ↑ / ↓ | 换行 | 好 |
| **长按 ↑** | 屏显三态循环：**整屏**（状态+行+进度+图例+诊断）→ **一行**（居中：状态+倒计时+已拍/跳过/未核实）→ **最暗**（只剩左上角一个状态词） | 已接通并定死语义（此前一秒内画两遍状态行、最暗模式反而带着图例和诊断） |
| **长按 ↓** | 演练模式开关（仅空闲时） | 本轮改绑（变焦杆不送达） |
| 中心（短） | 空闲=开始；完成/故障=确认返回 | 好；缺「取消」语义 |
| 中心（长） | 「标记：尚未实现」 | 待做 |
| TRASH（短） | 暂停 / 继续 | 好 |
| TRASH（长） | 停止运行（记为「已手动停止」） | **无确认**，见 P0-2 |
| MENU（短） | **直接退出 app** | **最大问题**，见 P0-1 |
| MENU（长） | 「菜单：尚未实现」 | 待做（PLAN §4.3） |
| 变焦杆 | 不送达 | 当它不存在 |
| AEL / C1 / DISP / PLAY | 吞掉，无绑定 | 可回收（P2-4） |

拍摄中不可编辑的行：**静音快门 / 驱动模式 / AEL**——它们只在开拍时下发给机身，运行中改只会让屏上写出机身没持有的值，所以本轮起直接拒绝并写明「运行中不改机身设置」。间隔/张数/延时/稳定延时仍可改；改**间隔**会立刻把时刻表按新值重排（从下一张起生效），不会把后面每一张的时刻整体挪走（[DECISIONS](DECISIONS.md) A19）。

### 本轮又修掉的（原 P1/P2）

- 机身侧设置**两个方向都下发**，并且开相机时用机身自己的值给计划打底（A25）：此前「本 app 打开过的静音快门永远关不掉」，屏上写着「关」而机身还是静音。
- 「静音快门」那一行的说明**写反了**（把开启状态的效果写在了关闭状态上）。
- app 被切走再回来时，**运行不再冻结**：干净收尾并报出已拍张数，同时重新打开相机、重新注册快门回调（A26）。
- 丢失松键的机身**不再把短按当成停止**：停止前问一次键本身（`SonyCamera.keyDown`）。
- 每帧五次的「卡根」全量走卡减为一次（只在根变化时重算）。
- **屏上减负**（A35）：`卡增/核实/落盘/读数/回执/机身`、`卡根/最新`、`曝光键`、字体路径与启动毫秒、相机能力摘要全部移出屏幕，写进卡上的会话日志；屏上只在出故障时留证据行、字体错误行、日志写不进一行。长按 MENU 的阅读器可以读设备报告与日志尾部。
- **机身周期改成实测**（A27）：被拒就是证据，面板诊断行出现 `机身 >X.Xs`（下界），被拒时直接说明「间隔太短」；按下窗口跟着快门回调延迟变长，长曝光不再被 2.5s 的常数掐断。

## 3. 验收方式（不允许只看构建绿）

1. 每一项都写成「真机动作 → 屏上应发生什么」，写在提交信息里。
2. **不涉及相机的部分先用演练模式（长按 ↓）验**：时刻表、倒计时、屏显三态、摘要屏的数字。
3. 涉及相机的部分按 [PLATFORM-FACTS](PLATFORM-FACTS.md) 的规矩记录：哪台机身、哪个固件、怎么测的。
4. 长时运行的手感（P1-3、P1-4、屏在几小时后是否还读得清）只能靠 1 小时以上的实拍 + 会话日志（PLAN §5.2 / M7）。

---

## 4. 明确不做

- 不加动画与过渡：CPU 与功耗在这个平台上是真实成本。
- 不加触摸支持，不为触摸留后路。
- 不加声音提示（含「拍到了」的提示音）。
- 不为好看加元素：**屏上每一行都必须能说出它对应的相机事实**。
- 不改 [DECISIONS](DECISIONS.md) A6 的键语义（方向=换行、左右=改值、滚轮=快速改值），除非有真机证据。
