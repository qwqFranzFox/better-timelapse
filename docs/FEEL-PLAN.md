# 手感规划（下一阶段）

这份文件只说一件事：**在相机上把 app 用起来是什么感觉**，以及下一阶段按什么顺序改它。
它不重复 [PLAN.md](PLAN.md) 的架构与里程碑，只写在真机上按下去、看见什么、以及哪里会让人骂人。

---

## 0. 为什么手感在这个项目里算功能

1. **相机上没有触摸屏。** 可用的键只有：方向键四个、中心、TRASH、MENU、滚轮与顶部拨盘。变焦杆这个键机身**不送给 app**（[PLATFORM-FACTS](PLATFORM-FACTS.md) §6），AEL / C1 / DISP / PLAY 目前被吞掉且无绑定。
2. **一次拍摄 30 分钟到几小时，用户会走开。** 回来时他只看一眼屏幕，那一屏必须能让他判断「成了没有、丢了几张、还能不能接着走」。
3. **误触的代价是整晚。** 老 app 的 U-01 就是这条：MENU 或 TRASH 一按，app 退出、运行丢失、什么都不问（[PAIN-POINTS](PAIN-POINTS.md) U-01/U-04）。
4. 因此本项目的两条手感判据（比「好看」重要得多）：
   - **任何一次误触都不能丢掉已经拍成的东西。**
   - **任何一屏都不能说出相机没做到的事**（U-06/U-07 的教训：数了没拍的帧、报了没生效的设置）。

## 1. 现状：键位与它们的实际行为

| 键 | 现在做什么 | 评价 |
|---|---|---|
| 滚轮 / 拨盘 | 当前行 ± 最小档 | 好；与 recipe-lab 的语义一致（[DECISIONS](DECISIONS.md) A6） |
| ← / → | 当前行 ± 大档 | 好 |
| ↑ / ↓ | 换行 | 好 |
| **长按 ↑** | 屏显三态循环：整屏 → 一行 → 只剩图例 | 本轮接通（此前是画好了但没有任何键能到达的死代码） |
| **长按 ↓** | 演练模式开关（仅空闲时） | 本轮改绑（变焦杆不送达） |
| 中心（短） | 空闲=开始；完成/故障=确认返回 | 好；缺「取消」语义 |
| 中心（长） | 「标记：尚未实现」 | 待做 |
| TRASH（短） | 暂停 / 继续 | 好 |
| TRASH（长） | 停止运行（记为「已手动停止」） | **无确认**，见 P0-2 |
| MENU（短） | **直接退出 app** | **最大问题**，见 P0-1 |
| MENU（长） | 「菜单：尚未实现」 | 待做（PLAN §4.3） |
| 变焦杆 | 不送达 | 当它不存在 |
| AEL / C1 / DISP / PLAY | 吞掉，无绑定 | 可回收（P2-4） |

拍摄中不可编辑的行：**静音快门 / 驱动模式 / AEL**——它们只在开拍时下发给机身，运行中改只会让屏上写出机身没持有的值，所以本轮起直接拒绝并写明「运行中不改机身设置」。间隔/张数/延时/稳定延时仍可改；改**间隔**会立刻把时刻表按新值重排（从下一张起生效），不会把后面每一张的时刻整体挪走（[DECISIONS](DECISIONS.md) A19）。

## 2. 已知的手感问题，按严重度

### P0 —— 会丢东西

| # | 问题 | 改成什么 | 怎么验证（真机） |
|---|---|---|---|
| P0-1 | **运行中短按 MENU 直接退出**，运行与计数全丢（U-01 的复现） | 运行中短按 MENU = 暂停 + 屏上要求确认（再按 MENU 退出 / 中心继续）；空闲时短按才退出，并执行退出规则 | 拍摄中按 MENU：应停下并询问，不应退出 |
| P0-2 | **长按 TRASH 立即停止**，无确认（600ms 就可能误触） | 长按期间屏上显示「松手即停止」进度条；松手才停 | 长按 TRASH：松手前不应停 |
| P0-3 | **退出规则未实现**：`Plan.revert()` 没有任何调用者，app 改过的静音/驱动/AEL 退出后留在机身上 | 开机读回机身实际值作为 `stored`，退出时把 `stored` 推回机身（[DECISIONS](DECISIONS.md) A10） | 改静音快门 → 退出 → 相机菜单里看是否还原 |

### P1 —— 少了就该有的

| # | 问题 | 改成什么 | 怎么验证 |
|---|---|---|---|
| P1-1 | **没有完成屏**（PLAN §4.5 / A11）：拍完只剩一句状态 | 摘要屏：已拍 / 核实 / 未核实 / 跳过 / 实测间隔 / 漂移 + 三个下一步（再拍一次、清空、最后一张文件名） | 拍 10 张到完成，看摘要是否与卡上文件数一致 |
| P1-2 | **中途停下或故障后只能重来** | DONE/FAULT 屏加「继续」：保留已拍张数与下一个序号，接着拍 | 暂停后再停止，按继续，看是否接着编号拍 |
| P1-3 | **关屏未实现**（`ROW_PANEL_OFF`，屏上已标「尚未实现」） | 先测 Sony 侧显示电源接口与 Android 亮度 0 的可行性（PLAN Q5），再决定实现或删掉这一行 | 真机试：屏灭后能否继续拍、能否唤醒 |
| P1-4 | 屏显「一行」模式信息太薄 | 那一行加上：下一张倒计时 + 已拍 / 跳过 | 真机看一行模式在 2m 外是否读得出来 |

### P2 —— 顺手

| # | 问题 | 改成什么 |
|---|---|---|
| P2-1 | 图例一行塞五条，编辑态/运行态需要的提示并不相同 | 按状态切图例：空闲=编辑提示，运行=进度与暂停/停止，完成=下一步 |
| P2-2 | 间隔档位手感（现在 ←→ ±1s / 滚轮 ±100ms） | 用真机常用值校准档位表（1s/2s/5s/10s/30s/1min 优先落在整数上） |
| P2-3 | 长按 ↑↓ 已被屏显/演练占用，无法用于「连续滚动」 | 重新分配：连续滚动改由「按住方向键 600ms 后」接管，屏显/演练挪到别的长按组合 |
| P2-4 | AEL / C1 / DISP / PLAY 四个键被吞掉却不做事 | 给它们真实用途：DISP=屏显切换、AEL=锁曝光开关、C1=标记当前张、PLAY=显示最后一张文件名 |
| P2-5 | 开拍前没有预检（PLAN §4.3） | 卡空间 / 电量 / 间隔是否 ≥ 机身下限，不合格就不允许开拍并在屏上说清是哪一条 |

## 3. 验收方式（不允许只看构建绿）

1. 每一项都写成「真机动作 → 屏上应发生什么」，写在提交信息里。
2. **不涉及相机的部分先用演练模式（长按 ↓）验**：时刻表、倒计时、屏显三态、摘要屏的数字。
3. 涉及相机的部分按 [PLATFORM-FACTS](PLATFORM-FACTS.md) 的规矩记录：哪台机身、哪个固件、怎么测的。
4. 长时运行的手感（P1-3、P1-4、屏在几小时后是否还读得清）只能靠 1 小时以上的实拍 + 会话日志（PLAN §5.2 / M7）。

---

## 4. 明确不做

- 不加动画与过渡：CPU 与功耗在这个平台上是真实成本。
- 不加触摸支持，不为触摸留后路。
- 不加声音提示（含「拍到了」的提示音）。
- 不为好看加元素：**屏上每一行都必须能说出它对应的相机事实**。
- 不改 [DECISIONS](DECISIONS.md) A6 的键语义（方向=换行、左右=改值、滚轮=快速改值），除非有真机证据。

## 5. 下一阶段的建议顺序

| 阶段 | 内容 | 为什么排在这 |
|---|---|---|
| **F1 安全** | P0-1 / P0-2 / P0-3 | 这三条都会「丢掉已经拍成的东西」，属于必须先修的类别 |
| **F2 收尾** | P1-1 / P1-2 | 一次拍摄的完整闭环：拍完能看懂结果、能接着拍 |
| **F3 省心** | P1-3 / P1-4 / P2-5 | 长时间拍摄的体验与「不让你白跑一趟」的预检 |
| **F4 顺手** | P2-1 / P2-2 / P2-3 / P2-4 | 键位与图例的打磨，风险最低，放最后 |

每一阶段的结束条件都一样：**真机上按一遍，屏幕说的与卡上发生的对得上。**
